# Stage 2: build the extraction documents

Require full recorded read coverage and no unfinished marker. Resume incomplete reads in Stage 1. Among complete inputs, take every compression with no extraction document of the same sha256 under `docs/extractions/` (search front matter for `sha256: <hash>`), and every compression rewritten since its document was built.

1. **Place and name.** Put the document at the mirrored folder. Session and meeting transcripts keep their file name. Other sources take a short lowercase-hyphen slug of their title, plus the version if they state one, because raw file names often mislead: `Model_Training (4).md` may be the newer revision, and unrelated files can share one name. Keep an existing filename stable. If a different source occupies the intended name, append the new hash prefix before the extension (extend until unique). For a batch, assign names in sorted source-path order.
2. **Find related sources.** Select candidates through the ledger (`docs/knowledge/sources.md`) and searches of `docs/extractions/` and the other new compressions. A candidate is any source that shares with this one:
   - the same sha256;
   - the same title, the same file stem with copy counters such as `(1)` or `(2)(1)` stripped, or the same series, such as numbered parts, versions of one document, or a recurring meeting;
   - a distinctive sentence from a user prompt, which re-exports of one conversation share;
   - a sentence this source quotes, which leads to the source it was quoted from;
   - a name under "Files it names";
   - a subject: match the names under "Subjects it names" against the registry (`docs/knowledge/subjects.md`) as [knowledge.md](knowledge.md) describes, and take the sources the ledger lists under those subject IDs.

   Matching finds copies but not rewordings, so read the About section and record headings of every candidate and of every source this one names, and ask of each pair: does one restate, revise, adapt, continue, contradict or judge the other? Documents revised or adapted from the same base are compared with each other too: list every pair first, siblings included, then compare each pair responsibility by responsibility (each component, owner, tool or choice that either names); every disagreement is a conflict. Read two tables on the same subject row by row: a reworded table is a restatement. A document that names its base only vaguely ("the reference document") is matched by its structure and subject, not left as an unknown name.

   Before deduplicating, also inspect tool-read and pasted-source passages in hook-captured sessions. Use their original paths/session IDs and actual matching content to locate earlier holders, even when the containing files have different hashes. A captured view gets a `Quotes` relation to the original when available and a Not held row for repeated specifics; keep its genuinely new records. If a view repeats another view, follow the provenance to the available original without inventing a missing link. Never count those copies as independent events, agreement, recurrence or corroboration.
3. **Hold once, by specifics.** When provenance establishes a reproduction of the same underlying statement or observation (a verbatim copy, containment, a re-export, a quotation, a second-hand summary, or a light rewording in another version), one document holds it and the other gets a Not held row: both line ranges, a link to the holder, and only what differs. Independent testimony, a fresh measurement or stronger first-hand evidence keeps its own record even when the specifics match. Route it as corroboration when scopes agree. Similar wording alone cannot establish copying. When a reproduction’s specifics differ, both documents hold their own, and the later one adds `Restates <link> L..` with what it dropped, added or changed. The holder is the document already written. Within one run it is the fuller copy, or the earlier one if they are equal. Keep holders stable for copies of equal provenance. Hold a quotation provisionally as second-hand until the original arrives. Then transfer the repeated passage to the original, replace the provisional record with a Not held row and a one-way `Quotes` link, and reconcile its subject, History, holding and ledger references to the original. Preserve distinct contributions and the audit trail without counting a second occurrence. Hold-once applies inside a changed section too: rows and lines that are word for word another version's are Not held. A table that repeats another document's rows and adds some holds only the added rows, with one Not held row for the repeated ones. When nothing differs, the Not held row says only where the passage is held. When a whole source is contained in another, such as an earlier cumulative export of one session, its document keeps About, the relation line and one Not held row for the whole range, and drops its own Files it names list.
4. **Relations.** Write the paired or symmetric relations on both documents. Write `Quotes`, `Restates` and `Mentions` only on the referring document:
   - `Revises` / `Revised by`: a later version of the same document.
   - `Supersedes` / `Superseded by`: a different source replaces it.
   - `Adapted from` / `Adapted by`: a separate document written from it as a base.
   - `Another export of`: two exports of the same conversation or session, including cumulative exports.
   - `Continues` / `Continued in`: a later part of the same session or conversation.
   - `Conflicts with`: name each point of disagreement.
   - `Quotes`: copies a passage of the other, including a pasted excerpt or appendix.
   - `Produced in` / `Produced`, `Judged in` / `Judges`: a source made the other or gives a verdict on it. Link the words of the person whose verdict it is.

   Give both line ranges and one clause of evidence. When you name turns or sections, use the sources' own headings and check the numbers in both sources. A `Conflicts with` line, in both documents, keeps each side's status (`decided by user`, `proposed`) and says whether anyone accepted either side. `Quotes`, `Restates` and `Mentions` are written once, by the source that makes them. Leave out names that occur only in lines held elsewhere. Names that match nothing held become `Names, not held at extraction: <name> (L..)`; that line stays true when the file arrives later.
5. **Write the document.** YAML front matter: `type: source-extraction`, `title`, `description`, `timestamp` (ISO 8601 with offset), `source`, `sha256`. Sections: About this source; Related sources (the relations, then the Mentions and Names lines made from the compression's Files it names); Records; Subjects it names (copied from the compression, without names that occur only in records held elsewhere); Not held here. Copy the records from the compression with links rewritten for the new location, and rewrite references to compression sections ("Files it names", "this file") to fit the document. Give several exports of one session distinct titles, for example by adding the part. Replace records held elsewhere with Not held rows that link the holder. Add a `Held at` column to the Not held table: a link to the holding document, `this document`, or `source` when the material is held only in the raw source. Every cross-document reference is a working relative link: before finishing, search the documents you wrote for placeholders or shorthand and for links whose file does not exist, and fix them. Keep links between rules and applications working when rewriting paths or linking to the holder under step 3.
6. **Reverse lines.** For a paired or symmetric relation, add its matching line to the earlier document. Except for provisional quotation holders, preserve its records: they still describe their unchanged source.
7. **Ledger.** Write or update the source's row in `docs/knowledge/sources.md` with the [ledger template](tables.md): every path, the first 12 characters of the sha256, the event date and its basis, the Ingested date, Stage `extracted` and a link to the document. Create the ledger from its template if it does not exist. An earlier document that gained only reverse lines keeps its row as it is.
8. **Navigation.** When the target uses directory indexes, every indexed folder has an `index.md` (no front matter) listing only its immediate children as `- [Title](file.md): <description>`, with subfolders linked to their `index.md`. On every subject type index under `docs/knowledge/<type>s/index.md`, `<description>` is the page's front matter `description`, copied word for word, and updated whenever the page's `description` changes. Create missing indexes up the tree, including the `docs/index.md` entry for `extractions/`. When the project uses a documentation changelog, add one bullet to it (for example `docs/log.md`) under today's `## YYYY-MM-DD` heading, newest first, naming the sources added or re-extracted, the skill used, any documents that got reverse lines, and any sources left out on purpose (for example an archive whose entries are unpacked, or helper transcripts the user did not ask for) with the reason.

Route the held records using [knowledge.md](knowledge.md). For re-extraction, see [maintenance.md](maintenance.md).
